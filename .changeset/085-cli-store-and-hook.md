`veilio scan --name <path>` scans stdin as the file `<path>` would be scanned, and `veilio scan --blobs <listing>` scans every file a `git diff --raw --no-abbrev` listing names, its content read by object id from `git cat-file --batch` on stdin. The pre-commit hook and the GitHub Action's diff mode now scan each changed file (added, changed, renamed or retyped) under its own name in one run, so a `.env` beside a code change, or one a `.gitattributes` `-diff` hides, is no longer committed; the hook says "could not check" when the check itself fails. A pinned Action `version:` older than this release fails the diff-mode step. The store refuses a map git tracks, one read or written through a link, one another user on the machine owns (unless listed in `VEILIO_TRUST_STORE_OWNER`; under sudo, the invoking user's store is readable, not writable), and a `.veilio/.gitignore` whose only pattern is not `*`; store files are replaced through an exclusive new file, never written in place. A wrong `confirmName` is refused without naming the map.
