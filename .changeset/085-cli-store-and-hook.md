`veilio scan --name <path>` scans stdin as the file `<path>` would be scanned, and the pre-commit hook now scans each staged file (added, changed, renamed or retyped) under its own name, so a `.env` beside a code change, or one a `.gitattributes` `-diff` hides, is no longer committed. The store refuses a map git tracks, one read or written through a link, one another user on the machine owns, and a `.veilio/.gitignore` whose only pattern is not `*`; store files are replaced through an exclusive new file, never written in place. A wrong `confirmName` is refused without naming the map.
