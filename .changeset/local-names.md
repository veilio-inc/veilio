A team member who cannot reserve numbers (the daily allowance, offline, the plan) now numbers new names in a local family, `__LOCAL_<tag>_<KIND>__n`, which never reaches the team's maps and is renumbered into team numbers on publish, so a teammate's restore is never wrong. Reservations are answered per kind, and a refusal is shown. Security fixes: a map's numbers floor a reservation only when Cloud issued them; a number planted above a member's block no longer forces every name local; the map and its side files are never written through a link; `restore_text` says plainly that its result puts the real names into the model's context.
